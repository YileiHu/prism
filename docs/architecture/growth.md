# 养成

> 模块 id `growth`，界面标签「养成」。四层模型（自知 / 分配 / 存量 / 行动）的软件落点：能力量表 + 挑战 + 赛季 + 元认知。数据全在 SQLite，不碰 vault 路径。
>
> 等级内部存 1–6，界面按游戏化方式显示为 **C / B / A / S / SS / SSS**（依次对应 知道 / 能做 / 胜任 / 精通 / 影响 / 宗师）；本文档里的 L3 即 A，L4 即 S。置信 C0–C5 用固定五格星条显示：C0 全空心，其余按 ★ 个数。显示映射只在 `levelGrade()` / `GrowthStars`，不改闸门与聚合。模块尚未随任何版本发布，因此 schema 只保留终态、不再保留历史迁移；开发库中的旧 growth 表在清理时一次性重建（见 `docs/ai/memory.md`）。

## 入口

- `src/components/growth/GrowthView.tsx`：模块根。侧栏 `GrowthSidebar` 经 `ModuleSidebar` portal 进全高槽位，是**唯一的视图导航**；元认知的三个分区也放在侧栏（「元认知」是固定分组：分割线 + 三个带图标行，不可折叠），工具栏作用域 `module:growth` 只放标题与上下文动作（能力页显示「新建能力」，其余视图各自有内联添加入口，不重复放切换控件）。
- 四个视图：`capabilities`（能力）、`challenges`（赛季）、`self`（元认知）、`chronicle`（编年史），侧栏顺序是能力 → 赛季 → 编年史 → 元认知，**默认进入能力页的全部领域视图**（工具栏标题始终是「能力」，页内筛选 chip 的「总览」只表示全部领域）；元认知的三个子项在工具栏分别显示「自知度 / 说明书 / 他评」。不再有独立的 `overview` 首页。空态统一为**无卡片**版式：整页空态用 `GrowthEmptyGuide`，区块/列表空态用 `EmptyState size="card"` 的纯文本行，不再包 `rounded-card` 容器。任务不是独立视图：能力页「总览」左栏由 `GrowthTasksCard` 独占整列（`GrowthTaskModal` 编辑，新建默认开始/截止都为今天；日期分组在 `src/lib/taskDates.ts`），也是应用里唯一排日期的行动入口；全局快速记录小窗也写入任务（不排日期）。`growth_tasks.capability_id` 把任务与能力连起来，任务完成不参与能力分。任务行是共享的 `GrowthTaskRow`：勾选块在行内（完成/重开）、整行点击打开编辑弹窗、右键菜单给编辑/完成/重开/删除；已完成行标题加删除线，能力徽章取所属领域的主题色；能力详情的「相关任务」列表复用同一行。
- **弹窗档位**：详情 / 写作统一 `Modal layout="document"`（能力 / 挑战 / 作品详情，挑战 / 作品 / 年度编辑，版本公告）：铺满窗口、四边 64px、固定头尾、只滚正文；正文按容器宽度分栏（能力 / 挑战 900、作品 880、年度 820），不额外限制内容宽度。短表单仍用 `sm/md/lg`，判据见 [UI kit](../guides/ui-kit.md)。
- 派生算法全部在 `src/lib/growth.ts`，组件不自己算分。
- 一次读：`growth:state` 返回 领域 + 能力 + 赛季 + 挑战 + 作品 + 预测（全部未兑现 + 近 90 天已兑现）+ 说明书 + 他评 + 年度一页。写操作后模块重新拉取（不做乐观更新）；跨模块写入（快速记录、设置导入）仍派发 `growth-changed`。快照点较多，全局曲线单独走 `growth:timeline`。
- **导出/导入**：设置 → 通用 → 养成数据。导出写单个 JSON（`format: prism-growth`、`version: 3`）：领域、能力（含父子关系/等级/置信/目标/时间戳）、全部证据、全部快照、赛季（含 focus/outcome/主题/封面变换）、挑战（含内容字段）、作品（含介绍/正文/图片）、任务（含所属挑战）、全部预测（含能力/挑战/任务链接）、自我说明书、他评、年度一页；赛季与作品的全部媒体文件以 data URL 嵌入 `covers`。导入只做**替换**：先写 `growth-backups/growth-before-import-<时间>.json` 自动备份，再在一个事务里清空并重建全部 `growth_*` 行与 `growth_media`，失败整体回滚；ID 会重新分配，能力/赛季/挑战/任务/作品的关联在新 ID 上重建（任务先于预测插入，预测的三个链接按映射表重指）。只接受 v3 文件；旧 v1/v2 备份不再导入。笔记、PDF、白板、设置、索引、收藏集都不在文件内，也不受导入影响。JSON 是明文，包含个人复盘内容，导出后自行保管。

## 对象关系

养成只有五类记录，**能力是唯一的评分锚点**；三类对象不并表，用外键连成一条链：

```
任务 ── 属于 ──> 挑战 ── 属于 ──> 赛季
  │                 │
  └── 练习 ──> 能力 <── 证明 ─┘
                  ▲
预测 ── 测量 ──────┘（可挂任务/挑战/能力，永不改分）
```

- **任务**（`growth_tasks`）：一次执行，有开始/截止，`completed_at` 为空即未完成；`challenge_id` 可空。挂挑战时能力由挑战补齐，显式能力与挑战能力不一致会被 `GROWTH_LINK_CAPABILITY` 拒绝；不挂挑战就是日常执行，不属于任何赛季。
- **挑战**（`growth_challenges`）：一次验证，能力可空（可空意味着没有评分对象）、赛季可空；过关是唯一的自动升级路径。
- **预测**（`growth_predictions`）：一次测量，`capability_id` 是锚点，`challenge_id` / `task_id` 二选一作为上下文（同时给会报 `GROWTH_PREDICTION_LINK`）；上下文会补齐能力，冲突同样拒绝。预测只进自知度，不改等级、置信或闸门。
- **赛季**只收纳挑战；任务经挑战归属赛季，没有「按日期自动归档」。
- **详情页互为上下文**：能力详情是文档型两栏——左栏顶部是一张 `SectionCard` 概览卡（header 用领域色 + 计数，body 含父能力/状态/过期、等级/分数、目标/差距、置信/半衰期/可携带/证据），下面是一张「定义与备注」卡（仅当有内容，正文 max-h 140 内部滚动），再下面才是挑战 / 任务 / 预测 / 证据四个 `SectionCard` + `tintColor` 列表卡（挑战 violet、任务 green、预测 blue、证据 gold；只染 header，身体仍是标准卡；各自内部滚动、无分节线）；右栏 380px 校准历史（`surface-inset` 凹陷框、上下撑满、单行记录、普通滚动条）；卡片页内容铺满面板，左右与底部都留 16px，宽屏页面整体不滚，单栏窄屏才整页滚，并显示本能力自知度。挑战详情列出任务 / 预测 / 作品。
- **删除语义**：删能力 → 挑战/作品/证据/快照级联，任务与预测保留、对应链接置空；删挑战 → 任务/预测/作品保留、链接置空；删任务 → 预测保留、链接置空；删赛季 → 挑战失去赛季。
- **什么时候用哪个**：任务 = 下一步做什么；挑战 = 能不能证明；预测 = 我事前判断得准不准。任务完成不写等级或置信，预测补实际也不写。


## 主流程

1. **首次进入**：领域表为空时按 i18n 名称建 6 个默认域（认知/表达/人际/执行/体能/专业，权重 .2/.15/.1/.15/.1/.3）；只建一次，之后只能在领域设置里改名/改权重。
2. **建能力**：`growth:create-capability` 写能力并立刻写一条初始快照；新建可直接指定初始等级（不算上调）。
3. **加证据**：`growth:add-evidence` 写证据并把 `last_evidence_at` 置为当前 UTC 时间。
4. **校准**：`growth:review-capability` 是唯一手动改分入口——上调需本次校准前的新证据、一次最多一级，L3 以上还需已通过挑战；同事务写快照。
5. **赛季**：`create/update/close-season`；当前赛季 = `closed_at` 为空的那条；`theme` 是海报主题色（标签调色板键），`cover` 是可选主题图。工具栏在赛季页保留赛季选择、新建赛季、编辑赛季、结算赛季（仅进行中）；新建 / 编辑共用一个季节弹窗（只改元数据），结算有独立的小弹窗（只写赛季结论）；不再有独立的新建挑战按钮，新建挑战走挑战区标题栏的「添加挑战」。海报有图时是深色带（主题色混 `--c-overlay`）+ 图片按 mask 从左到右渐显，无图时是主题色渐变。赛季页顶部是赛季海报（`GrowthSeasonPoster`：季序号、天数进度、通过环、本季挑战路径、结算结论），工具栏右侧的赛季胶囊下拉（`SelectButton variant="pill"`）可切换任意赛季回看，多赛季时才出现；点击海报挑战 chip 一律打开详情。选中赛季决定下方全部内容（挑战按 `seasonId`、作品按来源挑战或创建日期）。挑战筛选顺序是「全部 / 进行中」，进行中赛季默认「全部」；已结算赛季固定「全部」且不显示筛选。赛季可右键删除（`danger` + `ConfirmDialog`）：挑战保留但失去赛季，海报与封面文件一并回收。图片文件统一在 `%APPDATA%/prism/growth-covers/`，由 `growth_media` 表按 owner 记录文件名、排序、封面标记与裁剪 JSON；`growth:pick-cover` 只负责选图并复制，`growth:delete-cover` 与启动 GC 按引用清理（文件名由主进程生成，只允许该目录），经 `prism-growth-cover://` 协议读取。选图走赛季专用的 `GrowthImageField`（内部复用 `ImagePickActions`：选择 / 更换 / 移除 + 错误分类；空态、预览、裁剪一套 UI），主进程侧是通用的 `pickImageTo(dir, { title, maxBytes, maxWidth, jpegQuality })`：对话标题由渲染层本地化传入，宽度超过 2400px 时缩到 2400px；体积超过 2MB 时重新编码（PNG 保持无损、其余转 JPEG 82）；两者都不超时直接复制原图。**源文件只读不动**。选区是自由拖动 + 缩放（`GrowthImageField` 的 crop 模式：拖动改焦点、滑块 1–3 倍、重置、方向键/± 微调），存 `growth_media.transform`（赛季封面那一行；JSON `{x,y,scale}`，x/y 为 0–1 焦点），海报用 `object-position` + `transform: scale()`（`transform-origin` 同步焦点）渲染。换图/移除封面时，本次会话新选或替换掉的文件在保存后由 `growth:delete-cover` 删除；取消弹窗或弹窗被卸载时删除本次会话新选的文件，原图保留。
6. **挑战**：`create-challenge` 可挂能力与赛季，难度默认取该能力等级 + 1；新建 / 编辑只记录「概述 / 目标 / 通过标准」，过程（Markdown）在详情页随时编辑，复盘在结算时写。旧「做法」字段已删除，历史内容启动时并入过程。详情是文档型弹窗（宽时左侧定义 + 过程 + 结算复盘，右栏任务/预测/作品，窄时单列），空段不渲染。已结算挑战只锁能力 / 赛季 / 难度（`GROWTH_CHALLENGE_LOCKED`），标题、定义、过程与复盘仍可继续补写。赛季页挑战区标题栏右侧有「添加挑战」（与作品区的「添加作品」同款）；工具栏不再放新建挑战。
7. **结算**：`resolve-challenge` 写结果、归因、结果备注和复盘。弹窗是普通 `md` 小弹窗（不是文档页）：上方「结果」只放通过 / 未通过 / 放弃、归因和可选结果备注，下方「复盘」用较长文本域；不再在结算里顺手创建作品。过关时等级最多升到挑战难度（已更高则不变）、置信 +1、写快照并补一条 `usage` 证据，且必须选归因（`stats` 自己 / `buff` 平台）；未通过/放弃只记录、不动等级。结算后详情保持打开并显示结果与复盘。
8. **作品**：`create-artifact` / `update-artifact`。字段是标题、类型、日期、能力、来源挑战、一句话介绍（`note`）、Markdown 作品说明（`body`）、封面与图片画廊（存 `growth_media`）和链接。结算通过时可在同一弹窗顺手填标题 + 类型，之后再补内容。赛季页底部是**作品卡片墙**（封面 + 标题 + 介绍 + 元信息），点卡片打开作品详情（文档型：宽时左封面 + 右正文，窄时横幅 + 单列）；标题右侧只有打开链接 / 编辑两个图标，无链接时链接图标禁用；一句话介绍用左侧强调条，作品说明带「作品说明」小标题。卡片右键菜单是**编辑作品 / 打开链接（有链接时）/ 删除**，编辑直接打开作品编辑弹窗；删除也出现在编年史作品行。编辑弹窗是**文档型**（`layout="document"`）：上方是横向画廊（`GrowthArtifactGalleryField`：添加 / 移除 / 设为封面），下方宽时左右两栏——左栏标题、类型、日期、能力、来源挑战、链接，右栏一句话介绍 + Markdown 正文（`min-h-[34vh]`）；窄时单列。作品封面不做裁剪，卡片、详情与编辑预览统一按 `object-fit: cover` 居中显示。下拉菜单按视口剩余高度自动限高滚动，长挑战名换行不截断（`DropdownMenu` 统一处理）。简介为空时卡片用正文纯文本摘要，两者都为空显示「待补充」。封面与多图画廊统一写 `growth_media`（`owner_type='artifact'`，按 `sort_order` 排序，`is_cover` 标记卡片封面），文件复用赛季的 `growth-covers/` 与 `prism-growth-cover://`；选图 / 换图 / 取消由 draft hook 清理未保存文件，删除作品时数据库行由触发器删除、主进程按引用删文件，启动 GC 兜底。正文用模块私有的 `GrowthMarkdown`（精简 markdown-it，按需懒加载），只支持外链图片，不支持 wikilink / 嵌入 / 公式 / 高亮。
9. **总览（能力页的全部领域状态）**：独立首页已删除，也是默认落点。左栏由 `GrowthTasksCard` 独占并撑满高度；右栏上方是 `GrowthDomainDistribution` 领域分布雷达卡（点轴进入该领域），下方是全部能力列表卡；原来的六张领域雷达卡不再出现。单领域页保持「领域雷达 + 能力列表」不变。`GrowthTasksCard` 无标题、唯一快速输入（默认今天）+ 逾期/今天/未来 7 天/更晚/未安排 + 可展开已完成，已完成区头部的图标按钮经确认后一键清空，内部滚动。整个养成模块带一层统一的**轻动效**：切视图时内容上浮、卡片与列表错峰入场、准确率折线绘制、编年史曲线描边绘制、任务完成勾选波纹；只在进入视图或切换年份时播放，`prefers-reduced-motion` 下全部关闭。无数据时四个视图共用 `GrowthEmptyGuide`：一句模块说明 + 最多三步起步路径 + 一个明确 CTA（能力→新建能力，赛季→新建赛季/挑战，元认知→记预估/写说明书/记他评，编年史→去能力页），不再只显示一行「暂无数据」。不记录工时，也不再有预算/对齐卡；「每个时间段的主线」由赛季 focus、挑战和任务表达。
10. **预测**：两段式。开始前 `add-prediction` 只记预估（`actual` 留空 = 待兑现），做完后 `settle-prediction` 补实际。`actual` 为空的条目不进任何统计；`selfAccuracy` 取近 90 天已兑现条目的误差均值算自知度，`predictionBias` 看最近 5 条估时是否连续同向，`weeklyAccuracy` 出 8 周趋势（`settledPredictions()` 是唯一过滤点）。预测可带 `capability_id` 与 `challenge_id` / `task_id`（二选一）：从任务行「记一条预估」、挑战详情、能力详情或元认知入口创建时自动带上上下文，服务端补齐能力并拒绝冲突。
11. **元认知**：分区切换在**侧栏**——`GrowthSidebar` 里「元认知」是固定分组：顶部一条分割线，下面三个与主导航同款的 `NavItem`（自知度 / 说明书 / 他评，各带 14px 图标，图标与能力 / 赛季行对齐），不再使用 `SidebarSection`、凹槽 `sidebar-group` 或 `prism_growth_sections`，也不能折叠；选中项写回模块根的 `selfSection`，同时把视图切到 `self`。工具栏贡献 `growth:self-controls` 只剩当前分区的 `actions`（自知度 = 记一条预估，说明书 = 添加说明书，他评 = 添加他评）；工具栏标题与图标显示当前分区（自知度 / 说明书 / 他评，图标分别与侧栏的三个分区一致），不显示「元认知」。内容区不再有页头、只渲染当前分区。`add/update/delete-self-model` 维护 8 段自我说明书（能量/动机/拖延/偏差/学习/社交/价值观/盲区，每条带证据与置信）：说明书分区内容区顶部是一条 `ChipTabs`（「全部」+ 8 段，等宽铺满、不带条数；条数显示在「全部」视图的分段标题上），每段一个调色板颜色（`SELF_SECTION_COLORS`：能量金 / 动机砖红 / 拖延灰蓝 / 偏差紫 / 学习蓝 / 社交粉 / 价值观绿 / 盲区青），chip 上是色点，「全部」视图的分段标题、单段提示行和编辑弹窗的分段标签都带同一个点，条目的星级也用该段颜色，选中「全部」时按分段标题平铺，选中某段时只列该段条目；条目是笔记式的圆角行（无底色/边框，`rounded-control` + 悬停 `bg-hover/50` 高亮，陈述 + 证据 + 星级），点行即打开编辑弹窗（行内不再有按钮），删除走条目右键菜单（`danger` + `ConfirmDialog` 确认）；弹窗宽 520px、陈述 3 行、置信是等宽铺满的分段控件且下方显示所选等级的说明；新增/编辑走工具栏 `+` 或点击条目打开的 `GrowthSelfModelModal`（分段下拉 + 陈述 + 证据 + 星级置信），不再使用折叠卡片。`add-feedback` / `update-feedback` 记录和编辑他评（三问 + 与自评的最大偏差）；他评卡片点开或右键菜单进入编辑，删除走卡片右键菜单。自知度分区不用卡片：顶部一行「分数 + 已兑现条数 + 连续低估提示」，下方左右两栏（`lg` 起）——左栏是**误差时间轴**（每条已兑现预测一根柱：x=日期、y=归一化误差、颜色=类型、虚线=90 天均值，`fill` 撑满高度、最少 200px，hover 看对象/数值；柱子用 `useAnimatedValues` 从 0 生长、数据变化时平滑过渡，提示框按图表边界夹取，不会溢出或撑出横向滚动条），8 周折线固定在左栏底部；右栏 420px 的待兑现/已兑现列表。两栏各自滚动。
12. **编年史**：年份切换是工具栏右侧的**胶囊下拉**（`SelectButton variant="pill"`，与赛季页胶囊同一款，「全部」+ 有数据的年份，年份新的在前），**时间轴加载完成且确有数据时才出现**；空编年史不显示年份下拉，也**不显示编辑铅笔**（没有可编辑的年份），避免闪一下又消失；**默认选中年份为当前年份**；时间轴加载期间内容区显示骨架。选中年份后整页按年过滤——曲线用 `yearCurve(snapshots, 该年)` 重算该年 12 个月（当前年份只画到本月）；赛季按**日期区间是否与该年重叠**过滤（年份下拉同时收集开始年与结束年）；作品按 `createdOn`（缺失则 `createdAt` 转本地日期）的年份过滤；年度一页只看该年。`growth:timeline` 返回全部快照，`globalCurve` 取每月末「每项能力的最近等级」求平均，以**面积折线 + 赛季色带**呈现（色带用赛季主题色，虚线为 60 分参考线，悬停显示月份/分数/赛季），新能力不回溯拉低历史月份。赛季存档直接复用**赛季海报**（`GrowthSeasonPoster` 的 `expandable` 模式）：平时只显示海报头部（季序号、标题、主线、起止与天数、通过环），`group-hover` / `group-focus-visible` 时用 `grid-rows 0fr→1fr` 平滑展开挑战路径与结算结论；该模式下海报是只读的（挑战 chip 渲染成 `<span>`、不显示「+」节点），点卡片仍跳到赛季页并选中该季（`focusSeasonId`，侧栏切换时清空）。年度一页是**阅读卡**：顶部是自动数据摘要（年末分与年内变化、赛季数、作品数、升级次数、代表作前三），正文依次是引文式「变成了什么」、三件大事（`milestones`，JSON 数组最多三条）、两张「最该记住 / 最该丢掉」小卡、以及强调色的「明年只做一件事」（`next_focus`）。选中年份时它是该年的**头图**，排在赛季海报之前；「全部」时按年份倒序归档在最下方。编辑走工具栏铅笔或卡片上的铅笔打开 `GrowthAnnualModal`（按 `year` upsert；文档型弹窗，宽时左栏只读数据摘要、右栏写作表单，窄时摘要在上；年度卡右键菜单可删除该年），空白年份给出「写这一页」按钮。
13. **清档视图**：能力页的「清档」筛选只保留 长半衰期 × 高可携带 的能力，并显示 `portableShare`（随身资产比 = 可携带能力分 / 全部能力分）。
14. **技能树**：`parent_id` 表示前置能力，能力编辑弹窗里选「前置能力」；规则是同领域、最多两层、不能指向自己（`GROWTH_TREE_DOMAIN` / `GROWTH_TREE_DEPTH`，只有根能力可作父节点）。能力页按「根 → 子」顺序缩进渲染（`└` 连接符），父节点被筛掉时子节点回落为根行；移动领域会断开跨域前置，删除能力会先清空子节点的 `parent_id`。

## 不变量

- 等级只能由校准或过关改变；`growth:update-capability` 不接受 level/confidence。
- 上调必须有晚于上次校准的证据（`GROWTH_EVIDENCE_REQUIRED`）、一次最多一级（`GROWTH_LEVEL_JUMP`）；下调不限。
- **L3 以上每级需要一个已通过挑战**（`passed 数 >= level - 2`，`GROWTH_CHALLENGE_REQUIRED`）；过关不超过挑战难度，结算必须选归因（`GROWTH_ATTRIBUTION_REQUIRED`）。
- **关联一致性**：任务挂挑战时能力必须与挑战一致（挑战补齐空能力，冲突抛 `GROWTH_LINK_CAPABILITY`）；预测的 `challenge_id` / `task_id` 二选一（同时给抛 `GROWTH_PREDICTION_LINK`），上下文补齐能力且冲突同样拒绝；删能力 / 挑战 / 任务只置空任务与预测上的链接，不删记录。
- 已结算挑战只锁结构：能力 / 赛季 / 难度不可改（`GROWTH_CHALLENGE_LOCKED`），标题、定义、过程和复盘可继续补写；结果与归因不可改。删除挑战保留作品但断开关联。
- 作品正文是 Markdown 但不执行原始 HTML；封面只接受主进程生成的文件名，正文里的相对图片不解析；作品正文与封面不参与任何评分或闸门。
- 备份 v3；只接受 v3 导入，赛季与作品的全部媒体文件随 `covers` 搬运，导入后重建 `growth_media` 行。
- 养成表单图片：赛季封面走 `GrowthImageField`（`ratio="poster"` + `crop`）；作品走 `GrowthArtifactGalleryField`（只排序与选封面，不裁剪）。所有拥有者的图片统一存 `growth_media`（`owner_type` + `owner_id`）；后续他评头像只需加 owner type 和表单，不需要新表、新目录或新协议。
- 内容 modal（能力 / 作品 / 年度 / 说明书 / 任务）不直接放删除；删除入口在触发行 / 卡片的右键菜单（`danger`），确认走 `ConfirmDialog`；modal 内的子项列表（证据行）同样走右键菜单。
- 自知度、说明书**永远不进能力分**：它们是诊断数据，不是评分数据。
- 置信衰减是读取时计算（>90 天 −1、>180 天 −2），不写库、不跑后台任务；历史快照保留当时的判断。
- 归档能力不参与雷达聚合，但仍可校准与补证据；活跃上限 25 只是软提示；领域在能力存在时不可删。
- 全局曲线只统计「在该月末之前已有快照」的能力，新能力不回溯拉低历史月；`growth:timeline` 不做分页，个人规模可接受。
- 技能树最多两层且必须同领域：只有根能力能做父节点，父节点被归档或筛掉时子节点回落为根行显示。
- 事务数据在 SQLite，图片文件在 `%APPDATA%/prism/growth-covers/` 并由主进程维护：不触碰 vault 路径，不参与扫描、watcher、私密库与侧车文件。

## 验证

- 能力：无证据上调被拒；补证据后成功；升 L3 无通过挑战被拒；下调不拦；一次升两级被拒。

- 作品：卡片墙显示封面 / 标题 / 简介 / 类型 / 能力 / 日期；无封面用占位图，简介与正文都空时显示「待补充」；点卡片打开详情（封面大图、Markdown 正文），标题右侧有打开链接 / 编辑图标，无链接时链接图标禁用；卡片右键菜单含编辑作品 / 打开链接 / 删除，编辑直接打开编辑弹窗；一句话介绍有左侧强调条、作品说明有小标题；封面在卡片、详情与编辑预览中都按居中裁切显示（不提供自由裁切）；删除走卡片 / 编年史行右键菜单并确认；换封面保存后旧文件按引用清理，取消 / 卸载则删除本次新选文件；删除作品 / 级联删除能力后媒体行被清、文件由主进程或下次启动 GC 回收；在已结束 / 未来赛季添加作品，默认日期夹到该赛季区间。
